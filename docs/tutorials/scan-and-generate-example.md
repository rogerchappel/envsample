# Scan and Generate an Env Example

This tutorial uses `fixtures/basic` to show how envsample finds environment variable references without printing secret values.

## Build the CLI

```sh
pnpm run build
```

## Scan the fixture project

```sh
node dist/bin.js scan fixtures/basic --format text
```

Expected variables:

- `DATABASE_URL` from `compose.yaml` and `src/app.ts`
- `PUBLIC_API_BASE` from `scripts/start.sh` and `src/app.ts`
- `QUEUE_URL` from `compose.yaml` and `src/worker.py`
- `VITE_FEATURE_FLAG` from `src/app.ts`
- `WORKER_TOKEN` from `scripts/start.sh` and `src/worker.py`

The report also lists skipped secret-like files:

- `.env`
- `.env.example`

## Generate a blank example

```sh
node dist/bin.js generate fixtures/basic
```

The generated output starts with:

```dotenv
# Generated by envsample.
# Values are intentionally blank. Do not paste secrets here.
```

It groups keys by source file and leaves values blank.

## Add a CI guard

The repository includes a GitHub Actions example at `examples/github-actions.yml`:

```sh
npx envsample validate . --example .env.example --fail-on-stale
```

Use that pattern when a repository should fail CI for missing keys and stale example entries.

## Smoke check

Run the built-in smoke command before recording or sharing a demo:

```sh
pnpm run smoke
```
